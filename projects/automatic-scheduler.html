Automatic Course Scheduler

Built a Python application that generates semester schedules for University of Maryland Information Science students using degree requirements, prerequisite validation, real-time course data, seat availability, and scheduling logic.

Python • REST API • Object-Oriented Programming • CSV • JSON • Regular Expressions

View Code on GitHub →

Project Overview

Planning a semester can require students to compare degree requirements, prerequisites, course sections, available seats, and scheduling information across multiple sources. I developed the Automatic Course Scheduler to assist Information Science students with this process by combining program requirements with current course-section data and automatically generating a potential semester schedule.

The user enters completed coursework and can provide courses recommended by an academic advisor. The program then evaluates those courses and fills remaining space in the schedule with eligible courses based on academic requirements and course availability.

How the Scheduler Works

1. Student Information The student enters their name, semester, and completed courses.
↓
2. Advisor Recommendations The student can enter courses recommended by an academic advisor.
↓
3. Degree Requirements The program reads Information Science requirements, credits, categories, and prerequisites from a CSV file.
↓
4. Prerequisite Validation Completed coursework is evaluated against the prerequisite requirements for potential courses.
↓
5. UMD API Current section information is retrieved, including meeting days, meeting times, section numbers, and available seats.
↓
6. Course Filtering Completed courses, unavailable sections, invalid sections, and scheduling conflicts are filtered from consideration.
↓
7. Course Prioritization Remaining courses are considered according to their importance within the Information Science program.
↓
8. Recommended Schedule The program displays the selected courses, sections, meeting information, credits, and priority levels.
↓
9. Optional JSON Export The student can export the proposed schedule into a structured JSON file.

Core Features

Real-Time Course Data

Connects to the UMD API to retrieve current section information, including meeting days, meeting times, section numbers, and open-seat availability.

Prerequisite Validation

Evaluates completed coursework before recommending courses. The prerequisite logic supports required course combinations, alternative prerequisites, and course-level requirements.

Advisor-Assisted Scheduling

Allows students to enter courses recommended by an advisor before the program automatically fills remaining space in the semester schedule.

Seat Availability

Sections with no available seats are skipped so the scheduler focuses on sections that currently have open seats.

Schedule Conflict Checking

Compares selected sections by meeting day and start time to prevent identified scheduling conflicts from being added to the same proposed schedule.

JSON Export

Allows the completed schedule to be exported with student information, total credits, course IDs, sections, meeting information, priority levels, and available seats.

Course Prioritization

When the student's advisor-recommended courses do not reach the maximum credit limit, the program searches for additional eligible courses. Courses are prioritized according to their role in the Information Science degree requirements.

1
Benchmark Courses Considered first because they represent important progression requirements within the program.
2
Core Courses Required Information Science coursework is considered after benchmark requirements.
3
Elective Courses Eligible electives can fill remaining space after higher-priority requirements are considered.

Technical Approach

The application was built in Python using object-oriented programming. Student and course information is represented through classes, while program requirements are loaded from a CSV file. Regular expressions are used to standardize course codes entered in different formats.

The program connects to the UMD API using the Requests library and converts the returned section data into course objects that can be evaluated by the scheduling logic. Meeting times are converted into numeric values for comparison, while prerequisite and priority logic determines which courses are eligible for consideration.

After advisor-recommended courses are processed, the program can automatically select additional eligible courses until the schedule reaches its credit limit. Courses within the same priority level are randomized so the program does not always recommend the same elective options.

Current Limitations

  • The scheduler is currently designed specifically for the University of Maryland Information Science program.
  • Program requirements are stored in a local CSV file rather than retrieved dynamically from the university.
  • The scheduler uses the first valid available section it finds rather than comparing every possible section to determine an optimal schedule.
  • Current conflict checking compares meeting days and course start times and does not yet perform full time-range optimization.
  • The scheduler primarily focuses on Information Science coursework and does not currently account for every outside elective a student may need.
  • The application depends on the availability and accuracy of the UMD API.
  • The current command-line version does not allow students to browse and select preferred elective courses before the automatic schedule is generated.

Future Improvements

Web Interface

Multi-Semester Planning

Expand the scheduler beyond a single semester so students can plan a longer academic pathway toward graduation.

Additional Degree Programs

Course Exploration

Allow students to review course descriptions and select preferred electives before the final schedule is generated.

Explore integration with sources such as PlanetTerp so professor information can become another factor in future schedule recommendations.

Project Goal

The goal of this project was to reduce the amount of manual work involved in semester planning while applying programming concepts to a problem that students regularly encounter. Building the scheduler allowed me to combine API data, object-oriented programming, data processing, and decision-making logic into a practical application.
